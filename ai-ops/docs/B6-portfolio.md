# B단계 포트폴리오 — 검증 범위와 한계

기준일: **2026-10-23 KST**. [E1 종료 판정](B6-scope-and-exit.md)을 기준으로 한다. 배포된 흐름은 읽기 수집·규칙 자동 조사이고, 실제 모델 분석은 승인한 실습 입력 한 건의 로컬 비교까지 검증했다. B 전체와 C의 승인 기반 해결은 완료하지 않았다.

## 프로젝트 설명

EKS의 URL 단축 서비스를 대상으로 Kubernetes·Prometheus·Argo CD 운영 자료를 읽고 정제한 입력과 조사 보고서를 저장하는 시스템을 구축했다. Alertmanager와 실습 CI 기록을 영속 큐에 연결하고 대상/소유 UID·출처·최소 권한·중복 방지·재시작 복구·보관 정리를 적용했다. 기존 Slack·Watchdog 분기를 유지하며 자료가 부족하면 partial과 판단 유보를 기록한다.

배포 worker는 규칙 보고서를 자동 작성한다. 별도 로컬 도구에서는 실습 자료의 상태·설정 여부·집계 지표만 선별하고 전체 전송 미리보기와 입력별 승인을 거쳐 실제 OpenAI 보고서를 생성했다. 같은 정제 입력을 받은 규칙 요약과 모델 보고서를 비교했고, 원본 자료와 운영/실습 리소스가 보존됐음을 확인했다. 모델에 서버 조회·변경 도구를 제공하지 않았으며 production 자료 외부 전송은 계속 차단한다.

## 이력서 문장 예시

> EKS 읽기 전용 운영 조사 시스템에 경보·CI 기록 접수, 영속 큐, 자료 정제, 규칙 보고서와 중복·재시작·보관 제어를 연결했습니다. 별도 실습 자료를 최소 필드로 선별하고 입력별 승인·비용 상한 아래 실제 LLM 보고서 한 건을 생성해 같은 입력의 규칙 결과와 검토했습니다.

면접에서는 “자동으로 실행되는 부분은 규칙 조사이며 실제 모델의 상시 연결은 다음 설계 범위”라고 함께 설명한다. AI 사용 경험은 도구 호출 성공뿐 아니라 출처 보존·입력 선별·계약 검사·허위 주장 방지·비용/보관 제어와 실제 확인 범위를 근거로 제시한다.

## 아직 성과로 주장하지 않는 내용

일반 진단 정확도, 운영 장애 Top-1 적중률, MTTR·비용 절감률, 실제 Replica 장애 진단, 상시 모델 자동 조사, 사용자 승인 기반 자동 해결은 미검증이다. M3의 자체 검토는 독립 채점이 아니며 A7 합성 평가나 사람 수동 기준선을 대체하지 않는다. 원인 판단을 유보한 한 건을 정상 진단 성공으로 바꾸지 않는다.
