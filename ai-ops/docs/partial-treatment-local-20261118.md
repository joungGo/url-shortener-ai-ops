# 남은 partial 사유 처리와 로컬 검증 · 2026-11-18

## 목적과 기준

정상 요청 4건과 같은 관측 구간의 Slack 회신에서 지표 4종은 모두 확보됐다. 남은 로그 상한·빈 이벤트·범위 밖 배포 이력·실패/원복 이력을 서로 다른 제한으로 설명한다. 자료가 없다는 이유로 재배포나 장애를 만들지 않으며, `partial`을 없애기 위해 판정 조건을 낮추지 않는다.

구현 기준은 재설치 때 검증하고 로컬 bundle로 보관한 AI main `bc398ffb5513393ef031670ffdfbc5b95ed63630`이다. 기존 AI 기본 체크아웃의 main은 `ce96d46`에 있고 미커밋 작업이 있어 변경하지 않았다. 로컬 bundle에서 기준 커밋을 가져와 `codex/partial-evidence-treatment-20261118` 작업트리에서 구현했다. 원격 조회·push·PR·main 반영은 이번 작업에 포함하지 않았다.

## 항목별 처리

| 항목 | 처리 원칙 | 이번 구현 |
|---|---|---|

probe 외 HTTP는 probe로 분류된 경로 이외의 기록이며 업무 성공을 확정하는 지표가 아니다. 현재 Pod와 지표의 관측 사실은 별도로 보여주지만, 일부 출처가 비었거나 잘렸을 때 전체 서비스 정상·복구 완료를 선언하지 않는다.

## 구현 범위와 호환성

- `live_collectors/kubernetes.py`: 기존 이벤트 조회 횟수·UID 선택자·페이지/전체 상한·기한을 유지하면서 성공한 빈 목록과 조회 실패를 구분한다. 새 조회나 재시도는 추가하지 않았다.
- `data_policy.py`: 빈 이벤트 관측 표시가 잘못된 종류/상태이거나 다른 이벤트 증거와 충돌하면 저장 자료 재검증에서 거부한다.
- `evidence_coverage.py`, `result_explanation.py`: 검증된 증거·감사의 고정 코드, 줄 수, 정규화한 시각만 결과로 투영한다. 원문 로그·URL·예외·자격을 회신에 추가하지 않는다.
- 저장된 reason enum, 감사 schema version, 분석 규칙과 실행 허용 조건은 그대로다. 새 표시도 `missing/empty_response`이므로 이전 형식으로 읽을 수 있다. 구형 결과의 `ev-events-empty`는 전체 조회 성공이 확인되지 않은 빈 응답으로 표시하며 소급 승격하지 않는다.
- 새 빈 이벤트 표시도 수집/분석 관점에서는 missing 증거다. `partial`, 현재 상태 확인 불가, `execution_allowed=false`를 유지한다. 이번 작업은 표시·수집 진단 보완이며 정상 판정 정책 변경이 아니다.

실제 실패·원복 이력을 나중에 연결할 때도 원본 artifact의 출처·대상·revision·UID·시각·해시 검증을 유지한다. 현재 대상과 맞지 않거나 조사 범위 밖이면 현재 판단에 사용하지 않는다. 로그 한도를 높이거나 과거 이력을 새 시각으로 재포장하는 방식은 적용하지 않는다.

## 로컬 검증

`test_partial_treatment.py`에서 다음을 합성 응답으로 재현한다.

1. 관련 객체 3종 조회 성공 + 빈 목록: 성공한 빈 관측 설명, missing/partial 유지.
2. 403·시간 초과·페이지 잘림·잘못된 응답·소유 UID 불일치: 빈 성공으로 바뀌지 않음.
3. 과거 빈 결과: 새 성공 의미를 부여하지 않음.
4. 충돌하는 빈 이벤트 표시: 재검증 거부.
5. 상한에 도달한 probe/일반 HTTP/진단 혼합 로그: 실제 보존 표본 수·시각만 출력, 비밀 canary 비노출.
6. 오래된/잘못된 이력 시각: 원래 시각 참고 표시 또는 거부, 현재 증거로 승격하지 않음.
7. 기존 조회 수·요청 기한·runtime 설정 불변.
8. 기존 큐·worker 저장/재검증과 모의 Slack 동일 스레드 회신: partial/실행 거부 유지.
9. 확장 설명과 출처 인용 3개의 회신 길이 4,000자 이내.
10. 검토 후 보완: 원본과 부분 표본이 모두 상한에 걸려도 같은 로그 출처는 1회만 집계. 현재/이전 컨테이너는 구분.
