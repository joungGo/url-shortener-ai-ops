## 1. 승인 정책 전환 절차 (`slack_server transition-approval-policy`)

**문제.** 승인 장부는 처음 기록한 정책 hash와 현재 설정의 정책 hash가 다르면 시작을 거부한다. 진행 중인 승인이 바뀐 규칙으로 처리되지 않게 하려는 WF06 설계다. 그런데 이 상태를 풀 수단이 없었다. 그래서 승인자나 대기 시간을 바꾸면 relay와 ingress가 뜨지 않고, Slack 조사 회신까지 멈췄다.

**사용법.**

```
python -m ai_ops.slack_server transition-approval-policy \
  --config /etc/ai-ops --store /data/incidents --previous <이전 recovery-approval.json>
```

**동작.**

1. 새 설정(`--config`의 `recovery-approval.json`, 켜짐)과 이전 설정이 둘 다 있어야 한다.
2. relay와 ingress의 프로세스 잠금을 이 명령이 잡는다. 둘 중 하나라도 실행 중이면 거절한다. 운영자가 먼저 멈춰야 한다.
3. 장부가 없으면, 즉 한 번도 실행한 적이 없으면 `nothing_to_transition`을 돌려주고 승인 장부를 만들지 않는다.
4. 이전 설정의 정책 hash가 장부에 기록된 hash와 **정확히** 같아야 한다.
5. 새 정책은 `version`이 이전보다 커야 한다(기존 `replace_policy` 규칙).
6. 진행 중이던 승인(대기·승인됨·재검증 중·준비 가능)은 모두 `superseded`(`approval_policy_changed`)가 된다. 새 설정으로 relay를 다시 띄우면 "승인 정책이 바뀌어 이 요청은 대체되었습니다" 알림이 원래 스레드로 간다.
7. 출력에는 상태, 대체된 건수, 이전·새 정책 hash만 담는다. 실패하면 기존 고정 응답만 낸다(경로·내용 없음).

**운영 절차.**

1. 새 정책의 `version`을 올린다.
2. relay와 ingress를 멈춘다.
3. 이 명령을 실행한다.
4. 새 설정으로 다시 시작한다.

명령 실행 승인(`execute_command`) 장부는 아직 연결되지 않아 대상이 아니다.

## 2. tombstone·receipt 장기 정리

**문제.** 승인 장부는 보관 기간이 끝나면 기록을 tombstone(hash·시각만)으로 남기는데, 그 tombstone과 결정 receipt가 **영구히** 남았다. 이 둘은 장부 상한에도 포함된다(기록 10,000개, receipt 30,000개). 그래서 오래 운영하면 결국 "장부가 가득 참"으로 새 승인 대기를 열 수 없게 된다. WF07 준비 기록(`recovery_pr_links`, 상한 10,000)도 같았다.

**수정.** 보관 정리 tick에서 다음을 지운다.

- 승인 장부: 보관 종료(`retained_until`) 후 **30일**(`TOMBSTONE_SECONDS`)이 지난 tombstone과 그 계획의 receipt
- WF07: 같은 시점이 지난 준비 기록

**안전성.** 그 시점에는 원래 계획 자체가 만료돼 `load_plan`이 거절한다. 같은 계획을 다시 열거나 결정할 수 없으므로, 중복 방지 역할이 끝난 상태다(시험으로 확인).

## 3. 준비 뒤 관측 만료 알림 문구

**문제.** PR 준비가 끝난 뒤 관측 유효 시간이 지나면 장부가 `needs_review`(`observation_expired`)로 바뀐다. 이때 일반 문구 "자동으로 판단할 수 없어 사람의 확인이 필요합니다"가 나가서, 바로 앞의 "준비 완료" 알림과 이어지면 혼동을 줬다.

**수정.** 이 사유일 때만 전용 문구를 쓴다.

> 재확인 이후 현재 상태 확인이 오래되어 이 승인으로는 더 진행하지 않습니다. 준비된 PR 내용이 있어도 발행·변경은 하지 않으며, 진행하려면 새 승인 요청과 재검증이 필요합니다.

사유 코드는 그대로 붙는다. 다른 사유는 기존 문구 그대로다.

## 검증

신규 `test_recovery_small_fixes.py` 11개. 실제 WF05/06/07 fixture와 가짜 시계를 썼다.

**tombstone**

- 보관 종료 시점에는 tombstone만 남는다. 그로부터 30일에서 1초 모자란 시점에도 남아 있다. 30일이 되면 기록과 receipt가 모두 삭제된다.
- 삭제 뒤에도 같은 계획을 다시 열거나 결정할 수 없다.
- WF07 준비 기록도 같은 경계에서 삭제된다.

**알림**

- 준비 완료 → 관측 만료 순서에서 전용 문구가 나간다.
- 다른 `needs_review` 사유는 일반 문구를 유지한다.

**정책 전환**

- 진행 중 승인 1건이 superseded가 되고, 새 정책으로 시작되며, 대체 알림이 간다. 전환 전에는 새 정책으로 시작이 거부되는 것도 확인했다.
- 이전 정책이 일치하지 않거나 버전이 오르지 않으면 거절하고, 장부는 바뀌지 않는다.
- relay나 ingress가 실행 중이면 거절한다.
- 장부가 없으면 아무것도 만들지 않는다. 설정이 없으면 거절한다.
- CLI 성공 경로를 확인했고, 실패 시 경로를 노출하지 않는다.
