# B-06-E1 평가 범위·종료 조건 정리

판정일: **2026-10-23 KST**. E1 문서 정리는 완료했다. **읽기 수집·규칙 자동 조사와 승인한 실제 입력 한 건의 로컬 모델 비교는 검증했다. B 전체 완료와 C 실행 단계 진입은 보류한다.** 이 문서는 종료 판단이며 새 배포·장애 실험·모델 호출의 실행 기록이 아니다.

## 지금 되는 일과 연결되지 않은 부분

운영 경보 또는 실습 CI 기록 → 대상/출처 검사 → 영속 큐 → 읽기 수집 → 정제한 자료 고정 → **규칙 보고서** → 저장/조회가 배포된 자동 흐름이다. S10에서는 CI의 기존 롤백이 앱을 복구했고, 조사 시스템은 실패와 이후 상태를 설명했다. AI가 복구한 사례로 표현하지 않는다.

별도 로컬 도구에서는 실습 수집 자료 → 허용 필드만 선별 → 전체 입력 미리보기 → 사용자 승인 → 토큰 계산·**실제 모델 보고서** → 같은 입력의 규칙 요약과 비교까지 한 번 검증했다. 모델이 서버를 직접 조회하거나 변경한 것이 아니다.

두 흐름은 아직 자동으로 이어지지 않는다. 클러스터 worker는 규칙 전용이며 모델 비활성을 유지한다. 실제 모델 비교 한 건은 자료 부족 관측으로, partial/unknown을 계약에서 강제했다. 정상 서비스 판별이나 실제 장애 원인 적중률을 입증하지 않는다. [M3 결과](B6-model-projection-live-comparison.md)

최초 S3 v2의 후보 누락, S11 최초 원복 실패, 누락/stale 자료는 성공한 후속 결과로 덮어쓰지 않는다. A7 합성 평가와 B 실제 수집 비교는 모집단·조건이 다르므로 합산 점수를 만들지 않는다. A5/A7의 별도 미완료 조건도 E1로 소급 완료하지 않는다.

## 필수 후속 작업과 확장 범위

| 분류 | 항목 | 완료 판단에 필요한 일 |
|---|---|---|
| B 전체 완료 전 필수 | 배포된 읽기 조사와 모델 분석의 연결 | **B-06-M4**에서 실습 전용 연결을 먼저 설계한다. 정제 정책·입력 승인 방식·전송 상태/중복·예산·자격/통신·결과 검사를 worker에 어떻게 연결할지 정하고 구현·배포·최소 실제 검증을 별도 작업으로 나눈다. M3의 일회 승인을 상시 전송 승인으로 재사용하지 않는다. |
| B 전체 완료 전 필수 | 새 연결의 의미 검증 | 구현 뒤 명확한 정상 관측/제한된 장애·자료 부족에서 기대 문장과 금지 주장을 정한다. 현재 강제 unknown 계약으로 정상 진단 성공을 주장하지 않는다. 새 경로에서 필요한 사례만 검증하고 S1~S11 전면 반복을 요구하지 않는다. |
| B 전체 완료 전 필수 | 배포/실패 경계 | M2/M3 로컬 변경을 검토한 소스와 이미지에 반영한 뒤 실제 실습 경로의 전송 전후 중단·중복·한도·정리/중지 동작을 확인한다. 모의 검사가 적합한 실패는 모의로 검증하며 실제 429/timeout을 만들기 위한 유료 반복을 필수화하지 않는다. |
| 후속 확장 | 실제 Replica와 복제 지연·초기 Redis 연결 실패·JSON 세부 원인 | 현재 검증 범위 밖으로 남긴다. 해당 진단 기능을 성과로 주장하거나 구현을 바꿀 때 관련 사례를 추가한다. |
| 후속 확장 | 장기간 가용성·일반 정확도·MTTR/비용 절감률·독립 비교 | 기간/표본/비교군과 독립 평가가 없으므로 수치를 주장하지 않는다. E1 완료를 위해 새 대량 모델 평가나 사람 시간 측정을 요구하지 않는다. |
| C의 별도 필수 | 인증된 변경안 승인·실행·검증 | C-01~C-05과 R1~R8에서 구현한다. 첫 범위는 실습 앱의 이전 정상 이미지로 GitOps 복구다. 기존 CI 롤백이나 M3 전송 승인은 C 실행 승인 기능을 대체하지 않는다. |

M4는 연결 설계 작업이다. **이 문서의 작성으로 모델 키를 클러스터에 넣거나 egress를 열거나 production 자료를 외부로 전송하지 않는다.** production 전송은 계속 거부한다. 사용자에게 별도 계정·비용·데이터·변경 결정을 요청해야 한다면 구체적인 검토 결과를 만든 뒤 해당 단계에서 확인한다.
