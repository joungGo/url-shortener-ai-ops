# 로그·표본·이력 설명 보완 코드 검토

HTTP 접근·캐시 hit/miss/bypass 기록을 기존 정제 수집이 인식하지 못해 `no_diagnostic_fields`로 버렸다. 허용 형식의 메서드·상태 코드·probe/other·cache 신호만 보존하고 IP·URL·query·item_id는 제외한다. 공통 결과와 Slack은 지표별 표본 확보/요청량 0/시계열 누락/scrape 부족과 현재 배포/Argo 이력/검증된 CI 실패·원복 이력을 구분한다. 없는 표본이나 이력을 생성하지 않으며 실제 부족한 경우 `partial`을 유지한다.

## 검토와 보완

- 정규화 결과가 저장 후 동일하게 재검증되고 이전 진단 필드가 유지되는지 확인했다. 새 관측은 로그에만 적용하며 이벤트 정제는 유지한다.
- 검토 중 지원하지 않는 HTTP 메서드·상태/설명, cache 로그의 임의 추가 필드에서 URL/값 안 `RedisError`가 기존 자유 문자열 검색으로 넘어가는 결함을 발견했다. 합성 입력 4개에서 오인 추출을 재현했다.
- 알려진 access/cache 레코드가 허용 형식에 맞지 않으면 해당 줄을 제외한다. 자유 문자열 검색으로 재진입시키지 않는다. 미지원 형식을 성공한 수집으로 표시하지 않는다.
- 로그 줄 수는 요청 건수가 아니다. probe 200·현재 배포 정보가 전체 정상이나 과거 복구 성공을 입증하지 않는다. Prometheus increase는 추정 증가량이며 소수를 보존한다. 빈 시계열·scrape 표본과 트래픽 표본을 혼동하지 않는다.
- 기존 bundle/audit/report·권한 재검증, 고정 어휘, 같은 채널/스레드·런북 인용, 4,000자 상한과 `execution_allowed=false`를 확인했다.
- 변경 범위에서 추가 병합 차단 결함은 발견하지 않았다. 이 검토는 GitHub 사람 승인이나 실제 배포 검증을 대신하지 않는다.

## 검증

기존 Lease WIP를 제외한 깨끗한 main 기반 worktree에서 검증한다. 관련 55개 회귀 시험 통과. 새 시험 17개는 지원/미지원 로그, URL/추가 필드의 오류 표식 오인, 민감값 제거, 저장 재검증, 잘린 줄, 조회 경로·예산, 표본 0/누락/NaN/소수/scrape 부족, 현재/오래된/혼합 이력, 기존 큐·worker 회신과 출처·크기 제한을 다룬다.

전체 **1,206개 시험 통과(54.620초, 실패/오류/skip 0)**. 이전 로컬 1,210개에서 별도 Lease WIP 7개를 제외하고 검토 회귀 3개를 추가했다. 작업 조회·Slack 대역·런북 출처·요청 연결의 로컬 검사 4종과 저장소 경계 검사도 통과했다. 원격 PR CI는 기존 scope/contracts/image/terraform/Main PR Gate를 모두 확인한 후 일반 squash 병합한다. CI의 image는 통신 없는 빌드·실행 검사이며 이미지 등록·worker 배포는 아니다.

## 유지 조건과 후속

기존 분석기 버전·판정 규칙·증거/감사 스키마·PromQL/수집 예산·UID/시각 검증을 변경하지 않는다. 시작 15초·리뷰 최소 120초/마감 210초·소유 원복 240초/독립 원복 300초·회복 관찰 120초, 승인·잠금·실제 사람 리뷰·원복 조건은 유지한다.

실제 트래픽·exporter label 초기화와 검증된 이력 연결은 별도 후속 범위다. main 반영 후에도 실제 worker는 기존 이미지이며, 사용자 승인 범위의 이미지/worker 반영·사용자 시작 정상 조사 검증이 필요하다. 이번 작업은 배포·장애 실습·C04/C05 완료가 아니다.
